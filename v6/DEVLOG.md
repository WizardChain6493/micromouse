# v6 Dev Log — บันทึกการพัฒนา/ดีบัก

สรุปการเดินทางจาก v5 → v6 ทั้งหมด: เจอปัญหาอะไร วินิจฉัยยังไง แก้ยังไง และ**ทำไมถึงตั้งค่าแต่ละตัวแบบนี้**
เก็บไว้เพื่อว่าถ้าลืม หรือมีคนมาต่อ จะได้ไม่ต้องไล่หาเหตุผลใหม่

หุ่น: micromouse ESP32-S3 (N16R8), flood fill 5x5, VL6180X x4, MPU6050, encoder x2

---

## 1. ทำไม rewrite เป็น v6

v5 ทำงานได้แต่รก: dead code เยอะ (`turnPID` ที่ไม่ถูกเรียก, `alignFront` ที่ไม่เคยใช้, loop คอมเมนต์ทิ้ง ~100 บรรทัด), wall-following ประกาศตัวแปรไว้แต่ไม่ได้ต่อสาย, incremental flood ที่ซับซ้อนและพลาดง่าย

v6 = แยกโมดูล + แก้บั๊ก + เก็บพฤติกรรมที่ v5 พิสูจน์แล้วว่าดี:
- **Config.h** — ค่าคงที่/พินทั้งหมด จูนที่เดียว
- **Sensors** — ระยะ, gyro, encoder, ปุ่ม, LED
- **Motion** — มอเตอร์, วิ่งตรง, เลี้ยว
- **Maze** — แผนที่กำแพง + flood fill (ไม่ยุ่งฮาร์ดแวร์ ทดสอบแยกได้)
- **Log** — ส่ง log ออก USB + WiFi พร้อมกัน
- flood fill เปลี่ยนเป็น **BFS ใหม่ทั้งกระดานทุกรอบ** (25 ช่อง เร็วมาก ได้ค่าถูกเสมอ) เลิกใช้ `std::queue`

## 2. ไล่ปัญหาตามลำดับที่เจอ

### 2.1 เซ็นเซอร์ระยะ — FL/FR อ่าน 255 ตลอด
ตกใจว่าเสีย แต่จริงๆ VL6180X คืน 255 = "ไม่มีอะไรในระยะ" ตอนเทสไม่มีอะไรอยู่หน้าหุ่นเฉยๆ พอเอาของมาจ่อก็อ่านได้ปกติ → **เซ็นเซอร์ปกติ** ไม่ต้องแก้

### 2.2 ตัดสินใจ: วิ่งตรงใช้ encoder ล้วน ไม่ใช้เซ็นเซอร์ข้างเกาะกำแพง
ทำไม: **SL อ่านสูงกว่า SR ตลอด 3-11mm แม้หุ่นอยู่ที่เดิม** = เซ็นเซอร์สองตัว offset ติดตั้งไม่เท่ากัน ใช้ค่ากลางค่าเดียวกับทั้งคู่จะมี bias ค้าง หุ่นถูกดันไปข้างเดียวไม่หยุด
encoder ไม่มีปัญหานี้เพราะอ้างอิงตัวเอง (ล้อไหนนำก็ชะลอล้อนั้น)
เซ็นเซอร์ระยะเลยใช้แค่ **ตัดสินว่ามีกำแพงไหม** (ทำแผนที่) + เบรกฉุกเฉิน ไม่แตะการคุมทิศ

### 2.3 "ปัญหาโคตรเก่า" ตอนเคิฟขึ้นลง — หัวปัดตอนออกตัว/เบรก
ต้นเหตุ v5: ตอน ramp ความเร็ว `base` ลงเหลือ `MIN_PWM=35` แต่แรงแก้ทิศยัง swing ได้ ±65
→ `setSpeed(35-65, 35+65)` = `setSpeed(-30, 100)` **ล้อนึงถอยหลัง อีกล้อพุ่ง** หุ่นปัดหัว
แก้: `driveWithDiff()` รักษา **ผลต่าง** สองล้อไว้ ถ้าล้อช้าจะตกต่ำกว่าเกณฑ์หมุน เลื่อนทั้งคู่ขึ้นแทน ผลต่างเท่าเดิม ไม่มีล้อไหนถอย

### 2.4 เลี้ยว undershoot เกือบครึ่ง (90° → ~45°)
- แรกเดาว่า gyro ตันที่ ±250 dps → ขยาย range เป็น ±1000 (`GYRO_FS_SEL 2`)
- **แต่ log พิสูจน์ว่าเดาผิด**: `peak 250 dps` ที่เพดาน 1000 = 250 คือความเร็วหมุนสูงสุดที่มอเตอร์ทำได้ ไม่ใช่ขีดเซ็นเซอร์ (ตอนขูดกำแพง peak ตกเหลือ 124)
- ความจริง: `GYRO_SCALE = 90/47 = 1.915` ของ v5 มันแค่**ผิด** (ที่มาไม่ทราบ) พอ range กว้างพอแล้ว **ตั้ง `GYRO_SCALE = 1.0`** ให้มุมจริง → 90÷1.915 ≈ 47 อธิบาย undershoot พอดี
- บทเรียน: ควรใส่ตัววัด (peak dps) ในบรรทัด log ตั้งแต่แรก จะได้จับได้ว่าเดาถูก/ผิด

### 2.5 เลี้ยวแล้ว "เกิน → ดีดกลับ → ขาด" (limit cycle)
- `floor` PWM ถูกบังคับใส่ทุกครั้งที่ยังไม่เข้ากรอบ = ฝืน PID ไว้ ระบบชะลอตัวเข้าเป้าไม่ได้ → พุ่งข้าม → floor ดันกลับ → ดีดไม่รู้จบ
- แก้: **D เทอมเอา `yawRate()` มาตรงๆ** (`output = KP*err - KD_TURN_RATE*rate`) = ยิ่งใกล้เป้ายิ่งสั่งช้าลง ชะลอเข้าเป้าเอง
- floor ใส่**เฉพาะตอนหุ่นค้างจริง** (`rate < TURN_STALL_DPS`) ระหว่างหมุนปล่อยให้ PID เบรกเต็มที่
- จบเลี้ยวต้อง "เข้ากรอบ + นิ่งจริง" ทั้งคู่ (`rate <= TURN_SETTLE_DPS`) ไม่ใช่แค่บังเอิญผ่านเป้าตอนเหวี่ยง

### 2.6 Log ผ่าน WiFi (ถอดสายแล้วไม่เห็น serial)
- **ESP32-S3 ไม่มี Bluetooth Classic** (มีแต่ BLE) `BluetoothSerial.h` ใช้ไม่ได้ → ใช้ WiFi AP + telnet แทน
- `logPrintf()` ไม่ block รอเน็ต หย่อนลง ring buffer แล้วปล่อยใน `logPoll()` (นอกลูปคุม 200Hz)

### 2.7 Boot loop — `TG1WDT_SYS_RST` วนรีเซ็ต
ต้นเหตุ: **บอร์ด N16R8 ใช้ PSRAM octal กิน GPIO 33-37** แต่ `START_BUTTON = 35`
`pinMode(35,...)` ไปกวนบัส PSRAM พอ WiFi จองบัฟเฟอร์จาก PSRAM → ค้าง → watchdog เตะ
แก้: **Tools → PSRAM: Disabled** (เราไม่ได้ใช้ PSRAM) + ใส่ `#error` guard กันพลาดซ้ำ

### 2.8 Gyro not responding แต่อ่านได้ 2000 ตัวอย่าง (offset 0.00)
- MPU6050 ต้องการเวลาตั้งตัวหลังจ่ายไฟ ก่อนจะ ACK คำสั่งเขียน เดิมมี `WiFi.softAP()` คั่นเป็น delay โดยบังเอิญ พอย้าย WiFi ออกคำสั่งปลุกเลยหลุด ชิปหลับต่อ → รีจิสเตอร์คืน 0
- แก้: **probe จน MPU ตอบก่อนค่อยสั่ง** + **เขียนแล้วอ่านกลับมาเทียบ** (`mpuWriteVerify`) + พิมพ์ `WHO_AM_I` (ควรได้ 0x68) + **gyro ตายห้ามให้วิ่ง** (ค้างไฟแดง ไม่งั้น yaw=0 หุ่นหมุนติ้ว)

### 2.9 บั๊กแผนที่ (เจอจาก log)
- `stepForward` ปล่อยพิกัดหลุดขอบเป็น `(1,5)` แล้ว `canGo` อ่าน `walls[1][5]` นอกอาร์เรย์ → เพิ่มเช็คขอบ
- `mazeNextMove` คืน `'B'` ตอนทางตันโดยไม่บอกว่าหลังหันไปต่อได้จริง → เพิ่มเช็ค `mazeCanGo` ก่อนขับ
- บันทึกกำแพงหน้าจากเซ็นเซอร์**หลังเลี้ยวเสร็จ** (หุ่นนิ่ง/ตั้งฉาก เชื่อได้) แทนการเดาจาก ticks

### 2.10 เลี้ยว — **ไม่แตะ** (ตามที่เจ้าของหุ่นบอก)
v5 จูน PID เลี้ยวจนตรง 10 รอบติดได้แล้ว การเลี้ยวไม่ใช่ปัญหา เรื่องที่แก้คือ**เดินตรง**

## 3. มหากาพย์ "เดินไม่ตรง" (เบี้ยว 40° ใน 10 ช่อง)

ไล่ทีละชั้น ตัดตัวเลือกออกด้วยการทดลอง:

### ชั้น 1: gyro assist ไม่ช่วย
เปิด gyro ล็อกหัวตอนวิ่ง — ลองแล้วเหมือนเดิม (drift มอเตอร์สั่น+ชิปร้อน รบกวนพอๆ กับที่แก้) → **ปิด กลับ encoder ล้วน**

### ชั้น 2: MOTOR_BIAS_DIFF (feedforward) ก็ไม่ช่วย
ลอง -100 ถึง +100 หุ่นเบี้ยวซ้ายเหมือนกันหมด (ค่ามากๆ แค่ทำให้ส่าย)
**เหตุ: feedback กลืน feedforward** — `diff = KP_ENC*(encL-encR) + MOTOR_BIAS_DIFF` ตัว feedback แค่เลื่อนจุดสมดุลของ count หักล้าง diff จริงเท่าเดิม
→ พิสูจน์ว่าดริฟต์**ไม่ได้มาจากความเร็วสองล้อต่างกัน**

### ชั้น 3: เทส encoder/มอเตอร์ แยกกัน
- **เทส A (เข็นมือ 1m):** L=6539 R=6458 ต่าง ~1.25% (แต่ % ไม่คงที่ = ส่วนใหญ่ noise เข็นมือ) → **encoder สองข้างนับตรงกัน**
- **เทส B (PWM เท่ากัน open-loop):** R เดินมากกว่า 3.5% → **มอเตอร์ขวาแรงกว่า** และหุ่นดริฟต์ซ้ายตอนวิ่ง แต่**จบเอียงขวา** (เบรกตอนหยุด)

### ชั้น 4: แยก "ตอนวิ่ง" กับ "ตอนหยุด"
- **stop kick:** มอเตอร์ขวาแรงกว่า → เบรกแรงกว่า → ล้อขวาหยุดก่อน → หัวเตะขวาตอน brake
  แก้: **`STOP_DECEL_MS`** — ชะลอ PWM ลง 0 พร้อมคุมทิศ ก่อน brake (เดิม ramp ลงแค่ MIN_PWM แล้ว slam brake ทั้งที่ยังวิ่งอยู่)
- เจ้าของหุ่นเดาถูกว่า v5 มี "เคิฟลง" ตอนหยุด แต่ v6 ทำไม่ครบ

### ชั้น 5: continuous vs segmented → ดริฟต์แปรตามระยะ
วิ่ง 10 ช่องรวดเดียว (ออกตัวครั้งเดียว) เทียบวิ่งแยก → **ดริฟต์เท่ากัน** ไม่ใช่น้อยกว่ามาก
→ ตัด "การออกตัว" ออก (ไม่ใช่ตัวหลัก) ดริฟต์**แปรตามระยะ = เชิงกล**

### ชั้น 6: ต้นเหตุจริง = ล้อ/encoder นับต่อระยะไม่เท่า → `ENC_BALANCE_SCALE`
count เท่ากันแต่ระยะไม่เท่า (L นับเร็วกว่า → เดินระยะน้อยกว่า → โค้งซ้าย)
แก้ด้วย **scale คูณ encoder ขวาตอนเทียบ balance** — เปลี่ยน "นิยามของคำว่าตรง" ให้เล็ง*ระยะ*เท่ากัน ไม่ใช่ count เท่ากัน
**ต่างจาก MOTOR_BIAS_DIFF:** อันนั้นแก้ที่ output (feedback กลืน) อันนี้แก้ที่ setpoint (feedback กลืนไม่ได้)
พิสูจน์ว่าถูกตัว: **ปรับ scale แล้วดริฟต์พลิกซ้าย↔ขวาได้** (ถ้าเป็น toe เชิงกลจะพลิกไม่ได้)
ค่าที่ตรง ~1.003-1.004 (mismatch จริงแค่ ~0.3% ไม่ใช่ 1.25% ที่เข็นมือวัด)

### ชั้น 7: หัวเอียงสะสมต่อช่อง (ข้อจำกัดพื้นฐาน)
หลังแก้ scale: 5 ช่องแรกซ้ายนิดเดียว → แล้วเอียงขวาขึ้นเรื่อยๆ
= **kick เล็กๆ ต่อช่อง (<1°) สะสม** เพราะ encoder ไม่มีตัวอ้างอิงหัวสัมบูรณ์ ไม่มีอะไรดึงกลับ
แก้ให้สะสมช้าลง: **soft start** (ไต่จาก PWM 15 ไม่กระโดด 35) + **`STOP_DECEL_MS 500`**
แต่ลดได้แค่ให้ช้าลง **หยุดสะสมไม่ได้ด้วย encoder ล้วน**

## 4. สถานะปัจจุบัน

- ✅ ถึงเส้นชัยในสนามจริงได้แล้ว
- ⚠️ ยังไม่ตรง 100% ถ้าวิ่ง 10 ช่องตรงรวด (หัวเอียงสะสม) — แต่ในเขาวงกตจริงเลี้ยว/เจอกำแพงบ่อย สะสมไม่ทันโต

### ค้างไว้ / ขั้นต่อไป
1. **เปิด `alignFront` + ชดเชย offset 13mm** (FL อ่านต่ำกว่า FR) — จัดหัวตรงทุกครั้งที่เจอกำแพงหน้า = **reset การสะสมเป็นระยะ** โดยไม่ต้องพึ่ง gyro (ตัวหยุดสะสมที่แนะนำ)
2. **วงจรอ่านแบต** — ไม่แก้ความเบี้ยว (แบตตกกระทบสองมอเตอร์เท่ากัน) แต่ทำให้ค่าที่จูนไว้เสถียรข้ามระดับแบต = 10 รอบเหมือนกัน
3. re-calibrate `CELL_TICKS` วัดระยะจริง (ยังเป็นค่าเดา 1075)

### จูน CELL_TICKS
`DEBUG_CALIBRATE 1` วิ่ง 10 ช่อง วัดระยะจริง → `CELL_TICKS_ใหม่ = CELL_TICKS * (10 * CELL_SIZE_MM) / ระยะที่วัดได้(mm)`

## 5. ค่าจูนสำคัญ (Config.h) + เหตุผล

| ค่า | ตอนนี้ | ทำไม |
|---|---|---|
| `GYRO_FS_SEL` | 2 (±1000dps) | เผื่อหัวการหมุนอยู่กับที่ |
| `GYRO_SCALE` | 1.0 | ค่าจริงตามฟิสิกส์ (90/47 เดิมผิด) |
| `KD_TURN_RATE` | 0.12 | velocity feedback เบรกเข้าเป้า |
| `ENC_BALANCE_SCALE` | ~1.004 | ชดเชยล้อ/encoder นับต่อระยะไม่เท่า (แก้ดริฟต์) |
| `MOTOR_BIAS_DIFF` | 0 | ไม่มีผล (feedback กลืน) อย่าไปจูน |
| `STOP_DECEL_MS` | 500 | ชะลอลง 0 ก่อน brake กันหัวเตะตอนหยุด |
| `SOFT_START_PWM` | 15 | ออกตัวนุ่ม ไม่ให้มอเตอร์แรงกว่าพุ่งนำ |
| `START_BUTTON` | 35 | **ต้องปิด PSRAM** ไม่งั้น boot loop |

### หลักการที่ได้เรียนรู้
- **feedforward (แก้ output) ถูก feedback กลืน** — จะแก้ระบบปิดต้องแก้ที่ **setpoint** ไม่ใช่ output
- **ใส่ตัววัดใน log** (peak dps, encoder L/R) ก่อนเดา — จับได้ว่าเดาถูก/ผิด
- **แยกตัวแปรทีละตัว** ด้วยการทดลอง (open-loop vs closed-loop, continuous vs segmented) ตัดตัวเลือกออกทีละชั้น
- **encoder ล้วนไม่มีหัวสัมบูรณ์** kick ต่อช่องสะสมได้ ต้องมีตัวอ้างอิง (กำแพง/gyro) ถึงหยุดสะสม
